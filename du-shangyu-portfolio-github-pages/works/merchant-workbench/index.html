01 · 为什么做

商家运营的信息常分散在类目趋势、品牌盘面、商品表现、活动排期和复盘任务中。这个工作台希望把它们连接起来，让运营人员能够从盘面判断进入具体动作，而不是停留在数据浏览。

02 · 我独立完成什么

  • 定义工作台需要解决的业务问题与使用路径。
  • 拆解类目、货品、商家、活动和复盘五个环节。
  • 设计信息层级、交互与视觉界面。
  • 使用Codex完成前端实现、调试和GitHub Pages部署。

03 · 核心经营链路

FASHION COMMERCE / DECISION WORKBENCH
行业与类目→货品机会→商家承接→活动执行→数据复盘

每个模块不只展示数据，还给出判断依据和下一步任务，让问题、动作与复盘能够互相追溯。

04 · 关键功能

  1. 商家运营：导入匿名周度数据，识别GMV、订单和供给异常，并形成跟进任务。
  2. 货品经营：连接趋势证据、商品表现和经营优先级。
  3. 活动运营：将季节与经营节点组织成可执行节奏。
  4. 数据复盘：记录任务状态，让结果回流到下一轮判断。

05 · 我学到什么

AI Coding的价值不只是更快写出页面，而是迫使我把经验说清楚：输入是什么、判断依据是什么、动作如何被记录、结果怎样回到下一轮。这让原本依赖个人经验的运营方法变得更容易沟通和复用。
